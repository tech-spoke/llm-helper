## 設計議論で決まった重要な判断（v1.11_ja.md だけでは読み取りにくいもの）

### 1. 冪等タスクモデルの経緯

初期案では「初回登録」と「差戻し時の追加」を区別するサーバーロジックがあった。
議論の結果、**LLM が常に完全なタスクリストを送信し、サーバーはそのまま受理する**冪等設計に簡素化。
サーバー側で初回/差戻しの区別は不要。同じペイロードを再送しても同じ結果。

### 2. failure_count はタスク別

初期案ではセッションレベルの連続失敗回数だった。
議論の結果、**タスク分割した以上、どのタスクが何回失敗したかで介入判定すべき**となった。
`failure_count` は `Task` オブジェクトのフィールド。POST_IMPL_VERIFY で `failed_tasks` として報告されたタスクの failure_count をサーバーがインクリメント。

### 3. LLM はループを認識できない

コンパクト後、LLM は差戻しループに入っていることを認識できない。
そのため **全てのループ制限はサーバー側で強制**する設計。
- `intervention_count` (SessionState) — VERIFY_INTERVENTION の実行回数
- `quality_revert_count` (SessionState) — QUALITY_REVIEW からの差戻し回数
- `failure_count` (Task) — タスク別の検証失敗回数

### 4. code.md はセーフティネット

v1.11 のサーバーは自己完結型レスポンス（instruction + expected_payload）で LLM を誘導する。
しかし MCP はリクエスト/レスポンスモデルのため、**LLM が何も呼ばなくなった場合にサーバーからプッシュできない**。
code.md はこの「LLM 停止ケース」の唯一のセーフティネット。

**code.md に残すもの**: サーバーが教えられないこと（submit_phase を呼べ、get_session_status で復帰、フラグ解析、Intent 分類、並列実行ガイド）
**code.md から削るもの**: サーバーが動的に教えること（ペイロード仕様、遷移先、バリデーション、レスポンス例）

### 5. --quick と VERIFY_INTERVENTION

v1.10 で `--quick` は介入スキップ（介入❌）。v1.11 でもこれを維持。
フェーズマトリクスで Step 16 VERIFY_INTERVENTION の --quick は ❌。
POST_IMPL_VERIFY のサーバー処理で `-ni / --quick` は介入スキップとして同列扱い。

### 6. バージョン番号

元々 v1.13 として設計していたが、v1.11 と v1.12 の内容を吸収して **v1.11 にリネーム**。
現在の code.md ヘッダーは "v1.13" だが、これは旧番号体系。改訂時に v1.11 に統一する。

## 実装時の注意点

### やってはいけないこと

1. **旧 API を残さない**: 17 個の submit_* ツールは全廃止。互換レイヤーは作らない
2. **code.md に詳細ペイロードを書かない**: サーバーの expected_payload と二重管理になる
3. **TodoWrite に依存しない**: v1.11 ではサーバー強制のタスクオーケストレーション（Step 12-14）に置換
4. **☐☑ チェックボックスを残さない**: サーバーが状態管理するため不要

### 気をつけるべきこと

1. **start_session のレスポンス形式**: v1.11_ja.md のスコープ内だが、DESIGN_ja.md (code.md) 側の修正として一旦保留していた。実装時に整合させること
2. **Phase Enum の順序**: v1.11_ja.md に定義済み。EXPLORATION, SEMANTIC 等の既存値は維持し、新規値（BRANCH_INTERVENTION, Q1, Q2, Q3, POST_IMPL_VERIFY, VERIFY_INTERVENTION, MERGE 等）を追加
3. **READY の内部サブステップ**: Phase は READY のまま、サーバーが内部状態（plan/implement/complete）で Step 12/13/14 を区別
4. **探索ツール（query, find_definitions 等）は廃止しない**: submit_phase は「フェーズの出口」のみ。探索中に使うツールはそのまま残る

### 実装順序の推奨

```
1. tools/session.py
   - Phase enum 拡張
   - TaskModel dataclass 追加
   - SessionState にカウンター追加（intervention_count, quality_revert_count）
   - expected_payload 生成メソッド
   - フェーズ遷移ロジック

2. code_intel_server.py
   - submit_phase ハンドラ新設
   - Phase ディスパッチ（SessionState.phase でペイロード判定）
   - 自己完結型レスポンス生成
   - 旧 submit_* ハンドラ廃止

3. .claude/commands/code.md
   - 全面改訂（v1.11_ja.md の「code.md 改定方針」セクションに従う）
   - sample/code.md.v1.10 にバックアップ済み

4. テスト
   - v1.11_ja.md のテスト計画に記載のクラス群を実装
```
